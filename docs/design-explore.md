# 設計: 探索する（webhand-explore、webhand findings）

状態: 実装済み（PR #70）。実験 r63〜r67 を実施（「実験結果」）。末尾の「実装での決定」を参照。目的別スキルの第4弾。

## 目的

出力は「発見」（不具合の候補と、そこへ至る再現手順）。oracle がないので、2つのリスクがある。

- 範囲を越える: 探索は予定外のリンクを踏み、他のサイトや本番へ出ていく。
- 候補を判定と取り違える: 異常の信号は不具合の証拠ではない。

どちらも、仕組み（ブラウザ層の拒否、予算の上限）と報告の規則（候補、再現済みの区別）で抑える。

## 決めたこと

| 論点 | 決定 |
| --- | --- |
| 役割 | Claude: チャーター（方針）、許可ホスト、候補の解釈、再現の確認、報告。Jev: 操作選択。webhand: 記録と拒否 |
| 防護 | `start --explore --allow-domain HOST`（複数可）。許可外ホストへのリクエストはブラウザ層で中止し、`out_of_scope` として記録する。開始 URL も許可ホストの中でなければならない |
| セッション | `--explore` は `profile:NAME`（保存プロファイル）と `--read-only` と併用できない。`--auth NAME`（`auth save` で保存したテスト用アカウントのログイン）と `--file` は使える。ローカルの Chrome（chrome / headless-shell、`--chrome linux`）のみ |
| 予算 | `--max-total-actions N` が必須。試行ごとの上限に加え、セッション全体（`replan` をまたぐ）の上限。尽きたら `run` と `act` は終了コード 5 |
| 検知する信号 | `console_error`、`pageerror`、`http_5xx`、`request_failed`、`dead_end`、`out_of_scope` |
| 記録 | 信号の種類、URL の host+path（クエリとハッシュなし）、切り詰めた1行のメッセージ、直前の操作の番号。入力値は書かない |
| 判定 | `webhand findings` は候補を出すだけ。合否を出さない。再現は Claude が新しいセッションで同じ手順をやり直して確認する |
| 変更操作 | 既存の規則のまま。再試行しない。`MutationUncertain` で停止 |

## 変えない規則

- ページ本文とコンソールのメッセージは信頼しないデータ。
- モデルには番号だけを選ばせる。モデル呼び出しは増やさない。
- 失敗した実行もログから除外しない。
- 「見つからなかった」を「不具合がない」と報告しない。試した範囲を書く。

## 1. CLI

```
webhand start --explore --allow-domain HOST [--allow-domain HOST2] --max-total-actions N --goal "..." --url "..." --chrome linux
webhand findings [--id ID]
```

`--allow-domain` は host（と任意のポート）だけを取る。スキーム、パス、ワイルドカードは拒否。ホストは自身とそのサブドメインに一致し、ルールにポートがあれば一致が必要。`about:`、`data:`、`blob:` は外への出口ではないので通す。

### 信号

| 信号 | 取る方法 |
| --- | --- |
| `console_error` | `console` イベントの error。ただし「Failed to load resource」は応答と失敗が別に取るので除く |
| `pageerror` | キャッチされなかった例外 |
| `http_5xx` | 応答のステータスが 500 以上 |
| `request_failed` | `requestfailed`。`ERR_ABORTED`（遷移で起きる取り消し）と、自分で拒否したものは除く |
| `dead_end` | 操作の後のページに、待つ・タブを切り替える以外の操作がない。ブラウザのエラーページ（拒否した遷移の行き先）は除く |
| `out_of_scope` | 許可外ホストへのリクエストを拒否した。不具合ではなく、ページの記録 |

取るのは、`run` と `act` が動いている間だけ（コマンドがブラウザにつながっている間）。コマンドの間に起きたエラーは取れない。

### 出力

```
FINDINGS: 3 candidates (not verdicts: confirm each by repeating its steps in a new session)
1. http_5xx  localhost:3000/api/cart  status 500  (after step 1)
2. console_error  localhost:3000/  cart total is NaN  (after step 2)
3. pageerror  localhost:3000/  boom  (after step 3)
STEPS:
1. CLICK "Load cart"  (jev, /)
...
```

終了コード: 0 なし、9 候補あり。同じ信号・URL・メッセージは1件にまとめ、最初の操作の番号を示す。ログには `finding` イベントで、操作ごとに書く。

## 2. スキル /webhand-explore

1. チャーター、開始 URL、許可ホスト、予算、入力値（作り物）をユーザーと合意する。本番かどうか分からなければ聞く。
2. `start --explore ...` → `run`、毎回 `findings`。`STUCK`（3操作でページが変わらない）は、ログにエラーを出すだけのボタンでは普通に起きる。`act` か `answer`、`replan` で続ける。
3. 候補が不具合らしいかを読む。ノイズは、理由を言って除く。
4. 新しいセッションで手順を `act` でやり直し、信号が再び出たものを「再現済み」とする。
5. 報告: 信号、アドレス、メッセージ、手順、再現済み / 再現せず / 未確認、拒否した `out_of_scope`、試していない範囲。

## 安全

テスト環境に限る。`--auth` はテスト用アカウントのログインだけ（本番のアカウントは使わない）。ログインしたページは Jev（TypeSafe）に送られるので、実行前にユーザーへ伝える。許可ホストにはログイン先も含める。webhand は許可外ホストを拒否できるが、ボタンが何をするかは分からず、フォームを送信するのでデータが作られる。作り物の入力だけを使う。資格情報と支払い情報は入れない。

## 検証計画（実装後）

既知の不具合（JS の例外、500 応答、行き止まり）を仕込んだローカルページで、仕込んだ不具合の検出率と、仕込んでいないページでの誤検知率を測る（`~/webhand-ab` の rN、モデルは `--model claude-sonnet-5-5` に固定、失敗実行も除外しない、変える変数は1つ）。素の `/webhand` に同じ頼み方をした条件と比べる。許可外ホストへのリンクを置き、拒否が効くことも確かめる。

## 実験結果（2026-11-22、`~/webhand-ab` の r63〜r67）

fixture は、小さな店のページ `s0`〜`s4`（`s0` は正常、`s1`〜`s4` は不具合を1つずつ: 未知のクーポンで `pageerror`、数量9超の注文で 500、数量0の注文で行き止まり、数量を空にして `console_error`）。e = `/webhand-explore-research`、p = 素の `/webhand`（同じ依頼文）。le（d34443c）、Sonnet 5.5、失敗実行も除外しない。「見つけた」は報告の行のキーワード判定（一次判定）。

| ラウンド | 条件 | 仕込んだ不具合を見つけた |
| --- | --- | --- |
| r63 | e と p、漠然とした依頼、上限12 | 無効（fixture に入力検証がなく `s0` が正常でなかった） |
| r64 | 同、fixture を直した | e 1/8、p 0/8（操作が Checkout まで届かない） |
| r65 | e のみ、上限30 | e 4/8（fixture に税の丸め誤差が残っていた。探索がそれを見つけた） |
| r66 | e と p、漠然とした依頼、上限30、税を直した | e 2/8、p 1/8（差は誤差の範囲） |
| r67 | e と p、具体的な方針（境界値と異常値、未知のクーポン）、上限40 | e 7/8（実行できた 7 回では 7/7）、p 4/8（実行できた 6 回では 4/6） |

- 信号の記録は意図どおりに動いた。許可外ホストへのリンクは `out_of_scope` で拒否され、`refused.log` は常に空だった。
- 漠然とした依頼では差が出ない。仕込みの近くを指す具体的な方針では、e のほうが多く見つけ、報告に信号（`http_5xx`、`pageerror`、`dead_end`、`console_error`）と「再現確認済み / 未確認」の別が付いた。ただし r67 の方針は仕込みの近くを指していて、n も小さい。優位が確かとは言えない。
- r67 の3回（p2-s3、e2-s4、p2-s4）は、セッションが始まる前に時間切れになった（ログなし）。表の分母には入れ、実行できた回数を括弧に書いた。
- `s0` で「不具合」と報告されたもの（古い合計の表示、Checkout が未知のクーポンを通す）は、fixture の実際の挙動で、作り話ではなかった。fixture はこれを不具合とは扱っていない。
- 拒否した遷移が `dead_end` を出す問題を見つけ、直した（実装での決定を参照）。

## 実装での決定

- 2026-11-22: 当初は `--auth` と `--file` も拒否していたが、認証が要るアプリの探索とアップロードの試験に必要なので許可した。`profile:NAME` だけ拒否を続ける。
- 2026-11-22: `--explore` は `--id` と併用できる（セッションに名前を付けるだけ）。
- 2026-11-22: 許可外の拒否は `readonly.ts` のような操作ごとの拒否ではなく、ブラウザの `context.route` で行う（リンクのクリックは操作の種類からは分からないため）。
- 2026-11-22: 信号は `Browser.act` を経由する既存の流れの `onChange`（操作ごと）で書く。コマンドの終わりにも1回書く。
- 2026-11-22: 既存の `STUCK`（3操作でページが変わらない）は変えない。探索では、コンソールにエラーを出すだけの操作で起きるので、スキルに `act` で続けると書いた。
- 2026-11-22: 4xx は信号にしない（ログインが要るページの 401 や、存在しないファビコンの 404 が多く、誤検知になる）。実験で見直す。
- 2026-11-22: r64 で、拒否した遷移がブラウザのエラーページ（chrome-error://）に着地して `dead_end` を2件出すと分かった。エラーページでは `dead_end` を出さない（拒否は `out_of_scope` が示す）。
