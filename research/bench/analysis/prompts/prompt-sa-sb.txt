次の40セッションを対象にします。webhand は、Claude が計画し、Jev がブラウザを操作するエージェントです。
- sa（段階2の前）: ~/webhand-bench/work-sa/* と results-sa/* の20件
- sb（段階2の全体）: ~/webhand-bench/work-sb/* と results-sb/* の同じ20件
どの回にも invalid というファイルはありません（あれば、そのタスクは読まないでください）。
各セッションの trace.json、judge/judge_response.json、result.json、work-*/<ID>/home/runs/*/*.jsonl、
work-*/<ID>/outputs/ を読み、次のことを調べてください。

ここで数えたいのは「頼まれた作業が終わったか」です。値や内容が正しいかは数えません。たとえば、頼まれた
ページで頼まれた操作（検索、絞り込み、一覧の読み取り、フォームの入力など）を最後までやり、頼まれた形の
成果物や答えを出していれば、値が間違っていても「終わった」とします。

セッション（タスク × sa/sb）ごとに、次を判定してください。
1. 作業が終わったか: 終わった / 一部だけ終わった / 終わらなかった
2. 終わらなかった、または一部だけのとき、どこで止まったか（主なものを1つ）:
   - 目的のページに着けなかった（ボット確認、ログイン、地域制限、エラーページ、ページが見つからない）
   - ページには着いたが、必要な操作ができなかった（要素が見つからない、押しても変わらない、入力できない）
   - 一覧や結果の一部しか読めなかった（ページ送り、もっと見る、スクロール、iframe など）
   - webhand の試行の上限や時間切れで止まった
   - Jev が呼び出しを断った（ログの escalation の reason が JEV_FAILED）
   - Claude が途中であきらめた、または代わりの方法を試さずに終えた
   - Claude が終わったと判断したが、頼まれたことの一部をしていなかった
   - 利用者に返して（AskUserQuestion）、決まった答えで断られて終えた
   - 成果物を作らなかった、または頼まれた形でなかった
   - その他
3. 最後の webhand の結果（ログの escalation の reason、run_end、finish の status）
4. 止まったあと、Claude が別の方法（別のページ、検索、別の手順、replan、answer、act での手作業）を試したか: 試した / 試さなかった
5. 同じタスクで、sa と sb の判定（1）が同じだったか。違ったときは、その違いが webhand のどの動き
   （Jev の ESCALATE と Claude の answer、見えない領域（canvas、frame）の伝え方と早期停止、スクロール往復の停止、
   ログの stale や NOT_VISIBLE の違い、Jev の断り、その他）から来たかを、型だけで書く。webhand の動きとは
   関係のない違い（同じ条件でも結果が揺れる、サイトの側）と見えるものは、その型で書く
6. sb のセッションだけ: ログの escalation の reason が ESCALATE だった回、answer のイベントがあった回について、
   答えのあとに作業が進んだか（ページが変わった、別のステップに進んだ）を、進んだ / 進まなかった で数える。
   見えない領域（status.unseen、WHY に canvas、frame、plugin parts）が WHY に出た回があれば、そのあと
   Claude が別の道を試したかを、試した / 試さなかった で数える

型ごとに件数と、該当するタスク ID と sa/sb だけを書いてください。最後に、タスクごとの判定を
「タスク ID / sa / sb」の表にしてください。
- タスク文、ルーブリック、サイト名、URL、具体的な値、evidence の文面、ページの文章は書かないでください。
- 結果は ~/webhand-bench/analysis/completion-sa-sb.md に日本語で書いてください。ほかのファイルは作らないでください。
- benchmark/ のファイルや .enc は開かないでください。
